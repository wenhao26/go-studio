## 一、 项目背景与核心目标 (Background & Objectives)

在日常开发、运维和文件管理中，当面对包含数百万个文件的大型目录时，传统系统的统计工具（如 Linux 的 `du -sh` 或 Windows 资源管理器）常常面临**速度慢、无实时进度、I/O 阻塞严重、终端排版简陋**等痛点。

本项目旨在利用 Go 语言的并发优势（Goroutine 并发遍历 + 流式聚合），实现一个**极速、轻量、高并发且带美观终端交互（TUI）**的目录深度统计工具。

**产品形态界定**：单机、无守护进程、一次性执行的 CLI 工具。不提供 HTTP 服务、不连接数据库、不读取文件内容。

## 二、 核心功能与技术指标 (Core Features & Metrics)

### 1. 极致性能与超快速扫描 (High Performance)

* **并发架构**：采用固定规模的 Worker Pool（工作池）并发遍历目录树，最大化利用多核 CPU 与磁盘 I/O 吞吐量。
* **非阻塞流式处理**：边遍历、边计算、边聚合，避免一次性将海量路径或文件条目加载进内存导致 OOM。
* **内存与规模解耦**：内存占用不得随文件数量线性增长（待处理项仅保留遍历前沿，错误明细限流）。

### 2. 实时进度展示 (Real-time Progress)

* **动态交互终端**：进度以单行覆盖（`\r`）方式实时刷新，刷新间隔约 150ms。
* **实时指标**：展示当前扫描速率（文件数/秒、字节/秒）、已耗时、已扫描文件数与大小、当前正在扫描的目录路径。

> ⚠️ **本工具不提供百分比与 ETA（预计剩余时间）**。
> 目录遍历完成前，无法获知总文件数与总字节数，因此「剩余进度」在数学上不可得。强行基于历史平均值估算会输出严重误导的数字。本工具只展示可观测的量，这是刻意选择而非功能缺失。

### 3. 美观的主流软件排版输出 (Aesthetic Formatting)

* **现代终端美学**：使用结构化区块边框与色彩丰富的风格，输出对齐、清晰的结构化报告。
* **对齐必须基于显示宽度**：东亚宽字符与 emoji 在终端占 2 列，禁止按字节数或码点数计算宽度。
* **降级能力**：提供纯文本标签模式（`--no-emoji`）与无边框模式（`--plain`），用于 emoji 宽度异常或需要写入日志的终端环境。

### 4. 核心必含统计指标 (Mandatory Statistics)

统计结果包含 **4 项指标**（前三项为原始需求，第四项由需求裁决确定）：

| # | 指标 | 定义 |
|---|---|---|
| 1 | **扫描次数 (Scan Count)** | 系统实际执行的**目录节点访问总次数**（含递归子目录）。具体口径：成功**完整**读取的目录数，**含根目录**；读取失败的目录不计入，而是计入第 4 项 |
| 2 | **文件个数 (File Count)** | 目标路径下包含的全部文件总数（不含文件夹本身）。具体口径：**普通文件与特殊文件（FIFO / socket / 设备）**；**不跟随、也不计入符号链接与 Windows 目录联接（junction）**；**不对硬链接去重** |
| 3 | **路径总大小 (Total Size)** | 文件**逻辑大小**（`st_size`）之和。**不是磁盘占用**（`st_blocks × 512`）。硬链接重复计入；无权限文件按 0 字节处理并计入第 4 项 |
| 4 | **跳过错误数 (Skipped Errors)** | 因无权限等原因读取失败而被跳过的路径数。错误明细最多保留 20 条，在 `--verbose` 下展示 |

> **关于第 4 项指标**：本文档 §四.2 要求展示「跳过错误数」，与 R1 版本「统计结果必须且仅包含三项」互相矛盾。经裁决，跳过错误数**作为第四项统计指标**纳入报告，本表已为权威定义。

#### 4.1 智能单位转换策略

* 若总大小 $\ge 1\text{ GB}$，以 **GB** 为单位（保留两位小数，如 `14.52 GB`）。
* 若总大小 $< 1\text{ GB}$ 且 $\ge 1\text{ MB}$，以 **MB** 为单位（如 `450.20 MB`）。
* 若总大小 $< 1\text{ MB}$ 且 $\ge 1\text{ KB}$，以 **KB** 为单位。
* 若小于 1 KB，以 **Bytes** 为单位。

#### 4.2 单位换算的补充约定

* **基数采用 1024**，但显示沿用 `KB / MB / GB` 字样（不定长显示为 `KiB/MiB/GiB`）。
* **阈值判断必须在字节上完成**，禁止先换算再比较（避免边界抖动）。
* `Bytes` 档位为整数并带千分位（如 `1,023 Bytes`）；`KB / MB / GB` 保留两位小数。
* 边界行为（刻意保留 PRD 档位语义）：`1,048,575` 字节显示为 `1024.00 KB`，而非 `1.00 MB`。

#### 4.3 与 `du -sh` 的差异（预期行为）

| 差异点 | 本工具 | `du -sh` 默认 |
|---|---|---|
| 大小口径 | 逻辑大小 `st_size` | 磁盘占用 `st_blocks × 512` |
| 符号链接 | 不跟随、不计数 | 不跟随 |
| 硬链接 | 不去重、重复计入 | 按 inode 去重 |

选择逻辑大小的理由：跨平台语义一致（Windows 不暴露块数），且与 Go 标准库 `FileInfo.Size()` 对应；磁盘占用口径需要平台特定代码。以上差异必须在 `--help` 与项目 README 中显式声明。

## 三、 命令行参数与交互设计 (CLI & UX Design)

### 3.1 参数契约

| 参数 | 类型 | 说明 |
|---|---|---|
| `<路径>` | 位置参数 | 要统计的目录，最多一个；缺省为当前目录 `.` |
| `--path <dir>` | string | 命名参数指定目录，**优先于位置参数** |
| `--format <fmt>` | enum | `text`（默认）或 `json`；其他值视为用法错误 |
| `--output <file>` | string | 报告输出文件；缺省输出到 stdout |
| `--threads <n>` | int | 并发 worker 数量；`0`（默认）表示自动：`min(NumCPU, 16)`；取值上限 1024 |
| `--verbose` | bool | 输出诊断区：生效参数与错误明细；同时把诊断日志级别提升至 INFO |
| `--no-emoji` | bool | 用纯文本标签替换报告中的 emoji 图标 |
| `--plain` | bool | 省略报告边框，仅输出文本行；**不可与 `--format json` 同时使用** |
| `--version` | bool | 打印版本信息后退出 |
| `-h`, `--help` | bool | 显示用法说明 |

### 3.2 用法示例

```bash
# 基础用法：统计当前目录
faststat .

# 指定目标路径并开启详细模式
faststat --path /var/log --verbose

# 导出结果为 JSON 格式（便于程序对接）
faststat --path /data --format json --output result.json

# 机械硬盘上限制并发，避免寻道放大
faststat --path /data --threads 2
```

### 3.3 退出码契约

| 码 | 含义 |
|---|---|
| `0` | 扫描完成（**可能包含被跳过的错误**，错误数在报告中单独展示） |
| `1` | 运行失败：根路径不存在/不是目录、报告写入失败、被用户取消（Ctrl-C / SIGTERM） |
| `2` | 命令行用法错误 |

### 3.4 输入输出分流契约

| 通道 | 内容 |
|---|---|
| `stdout` | **只**输出最终报告（text 或 json），必须可直接被管道或程序解析 |
| `stderr` | 进度渲染、结构化诊断日志、用法错误提示 |

* 进度渲染仅在 **stdout 连接到终端** 且 **`--format text`** 时启用。`--format json`、管道与 CI 环境下一律禁用，否则 JSON 将不可解析。
* `--output` 写文件必须采用「临时文件 + rename」原子写入，失败路径清理临时文件，禁止留下半截 JSON。

### 3.5 终端结果排版样式示例

```text
╔════════════════════════════════════════════════════════╗
║                🚀 FASTSTAT SCAN REPORT                 ║
╠════════════════════════════════════════════════════════╣
║ Target Path  : /Users/developer/go-studio              ║
║ Status       : Completed (Duration: 1.24s)             ║
╠════════════════════════════════════════════════════════╣
║ 📂 扫描次数 (Directories Visited) : 12,450             ║
║ 📄 文件个数 (Total Files Found)   : 148,203            ║
║ 📦 路径总大小 (Total Size)        : 4.82 GB            ║
║ 🚫 跳过错误数 (Skipped Errors)    : 3                  ║
╚════════════════════════════════════════════════════════╝
```

> **对 R1 示例的修正**：R1 版本的分隔行写作 `╠……╝`（左端为三叉连接符、右端为右下角），属于不合法的边框组合。R2 修正为 `╠……╣`。
>
> **排版约束**：内容区固定 56 列（不含左右边框），全部行的显示宽度必须严格相等；超长内容截断并追加省略号，保证边框不错位。

### 3.6 `Duration` 显示精度

* 大于等于 1 秒：保留两位小数的秒（如 `1.24s`）。
* 小于 1 秒：保留一位小数的毫秒（如 `12.5ms`）。
* 理由：目录扫描常在毫秒级完成，统一按秒显示会得到 `0.00s`，让用户误以为工具未测量耗时。

### 3.7 JSON 输出契约

```json
{
  "target_path": "/data",
  "status": "completed",
  "duration_seconds": 1.24,
  "statistics": {
    "directories_visited": 12450,
    "total_files": 148203,
    "total_size_bytes": 5175123456,
    "total_size_human": "4.82 GB",
    "skipped_errors": 3
  },
  "tool": {
    "name": "faststat",
    "version": "1.0.0"
  }
}
```

* `status` 取值：`completed` | `canceled`。
* `total_size_bytes` 为无精度损失的整数字节；`total_size_human` 仅供展示，程序对接须使用前者。
* `--verbose` 时追加 `error_details: [{path, error}]`；默认不输出。
* **不套用** HTTP 统一响应体 `{code, message, data, trace_id}`：本地一次性进程不具备这些语义。

## 四、 非功能性约束与工程边界 (Non-functional Constraints)

### 1. 跨平台兼容性

支持 Linux (x86_64/ARM64)、macOS (Apple Silicon/Intel) 及 Windows 10/11。

* 计数与大小必须使用 `int64`，禁止使用平台相关的 `int`。
* 终端宽度计算需显式固定策略，禁止依赖运行时 locale 推断，否则同一份代码在不同机器上会产出不同宽度的报告。
* Makefile 类任务脚本需在文档中说明 Windows 下的执行方式。

### 2. 错误与权限处理

* 遇到无权限访问的子目录（如 `Permission Denied`）时，**系统不能崩溃、也不能中断扫描**，必须记录并在最终报告的「跳过错误数」（第 4 项指标）中展示。
* 根路径不存在或不是目录时，**立即失败**并返回退出码 `1`，不产出误导性的「0 个文件」报告。
* 读取中途失败时，已成功读出的条目仍参与统计，该目录不计入「扫描次数」，错误计入「跳过错误数」。
* 用户取消（Ctrl-C / SIGTERM）时优雅停止，输出已统计到的部分结果，状态标记为 `canceled`，退出码 `1`。

### 3. 性能验收指标

> **状态：草案，待需求方确认数值后转为正式验收标准。**
> 在数值确认前，不进行基准断言，也不宣称「高性能」已被验证。

| 指标 | 建议目标（待确认） | 验证方式 |
|---|---|---|
| 吞吐 | 100 万文件 / 50 GB 数据集，NVMe SSD 上 ≤ 60s | `go test -bench` + 固定数据集人工基准 |
| 峰值内存 | ≤ 256 MB，且**不随文件数线性增长** | 扫描 10 万 vs 100 万文件对比 RSS |
| CPU 并行度 | 多核并发吞吐不低于单 worker 的 4 倍 | 基准对比不同 `--threads` |
| 小目录开销 | 目录内容 < 1000 文件时总耗时 ≤ 200ms | 基准测试 |

### 4. 遵守根目录统一规范

* 代码编写与错误处理严格对齐 `go-studio` 根目录下的 `AGENTS.md` 全局约束。
* 依赖包选择必须遵循 `docs/development/dependencies.md` 白名单。**引入白名单之外的任何依赖前，必须先按 `docs/README.md` §3 的流程更新白名单规范并通过审查，再修改代码。**

## 五、 安全要求 (Security Requirements)

| 风险 | 要求 |
|---|---|
| **终端转义序列注入** | 文件名与路径属于不可信输入。输出前必须剥离 C0/C1 控制符、DEL 与 U+2028/U+2029，阻断 `\r` 覆盖已输出行、OSC 52 写剪贴板、篡改终端标题等伪造手段 |
| **链接逃逸与成环** | v1 一律不跟随符号链接**与 Windows 目录联接（junction）**，既避免遍历越出目标目录，也避免环状链接导致无限遍历。注意 junction 在 Go 中表现为 `ModeIrregular` 而非 `ModeSymlink`，必须额外跟随一次才能识别，否则会被误计为 0 字节文件 |
| **路径输入** | 路径必须经 `filepath.Clean` 规范化后再进入遍历层；不得经过 shell 展开 |
| **凭据泄漏** | 不得读取或记录任何凭据；版本号由构建期注入，源码中禁止出现密钥 |
| **输出原子性** | `--output` 必须原子写入，失败路径清理临时文件 |
| **资源收敛** | 并发度必须有硬上限；取消时必须唤醒所有等待者，不得泄漏 goroutine |
| **日志通道** | 诊断日志只写 `stderr`，禁止污染可被管道解析的 `stdout` |

## 七、 明确不在 v1.0 范围内 (Out of Scope)

按 `AGENTS.md` §70「当前真实需求 > 假想未来需求」，以下能力 v1.0 **不实现**：

* `--exclude` 排除规则、`.gitignore` 语义支持
* `--max-depth` 深度限制、`--follow-symlinks` 跟随符号链接
* Top-N 大目录排行、图表化输出、历史对比
* 配置文件（仅支持命令行参数）
* 分布式 / 多机扫描、守护进程模式
* 颜色主题定制

以上能力若需要，应作为独立需求提出并重新评估。
