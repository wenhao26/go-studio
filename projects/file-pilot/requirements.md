## 一、 项目背景与核心目标 (Background & Objectives)

### 1.1 背景与痛点

现代用户电脑中长期积累大量文件：下载目录混乱、微信/QQ/浏览器产生无规则文件、图片视频文档混杂、文件名不可读、手动整理成本极高。传统方式只能按扩展名查看，无法理解文件用途，无法自动形成合理目录结构。

### 1.2 产品定位与原则

> 面向个人用户的**智能文件整理助手**（桌面应用，非服务、非守护进程）。

核心价值：扫描文件 → 理解属性 → 生成整理建议 → 用户确认后完成整理。

| 产品原则 | 在 v1 的落地定义 |
|---|---|
| 不直接修改用户文件 | 只读扫描 + 同卷 `rename` 移动；**永不写入/截断/删除任何用户文件内容**；v1 无任何删除类操作 |
| 所有整理行为必须可预览 | 整理前必须展示分类结果与逐文件归属，用户可调整；执行前必须弹二次确认 |
| 所有操作必须可撤销 | v1 实现**撤销上一次整理**（FR-11），基于持久化的操作记录反向移动 |
| 所有过程必须透明 | 扫描/分类/整理全过程实时日志 + 进度；所有文件移动落操作记录（可审计） |

### 1.3 产品目标

**MVP（v1）**：目录选择、扫描、实时过程展示、规则智能分类、分类预览与调整、确认后移动整理、撤销上一次整理、扫描统计、整理报告。

**长期（不在 v1）**：自动整理下载/微信目录、图片管理、重复文件清理、文件生命周期管理、用户习惯学习。

## 三、 总体用户流程 (User Flow)

```text
打开应用
  → 选择扫描目录（系统选择器 / 最近目录）
  → 配置扫描参数（并发、隐藏文件、系统文件、大文件）
  → 开始扫描（任务创建，实时进度 + 日志）
  → 扫描完成（自动完成分类，生成扫描统计）
  → 查看智能分类预览（分类汇总 → 分类详情）
  → 调整分类结果（逐文件改类别 / 排除出本次整理）
  → 确认执行整理（二次弹窗：数量 + 目标目录）
  → 整理执行（实时进度 + 日志）
  → 查看整理报告（成功/失败/耗时/数据量）
  → （可选）撤销上一次整理
```

状态机级别约束：同一时刻**至多一个活动任务**（§6.3）。

## 四、 功能需求 (Functional Requirements)

### FR-1 首页：目录选择

| 项 | 需求 |
|---|---|
| 输入 | 系统原生目录选择器（Wails 对话框）；或点击最近扫描目录（最多 5 条，来自 `settings`） |
| 成功 | 展示已选绝对路径；「预计文件」显示**未知**（不预扫描、不估算） |
| 取消 | 展示 `目录选择失败 / 原因: 用户取消操作`，不创建任务 |
| 未选目录点开始 | 前端拦截提示 `请选择扫描目录后继续`，不调用后端 |

### FR-2 扫描配置

| 配置项 | 类型 | 默认值 | 校验/语义 |
|---|---|---|---|
| 扫描并发数 | int | CPU 核数（钳制到 [1,64]） | 允许 1–64；非法值立即报错，**不静默钳制** |
| 扫描隐藏文件 | bool | false | true 时纳入 `.` 前缀 / Windows 隐藏属性文件 |
| 扫描系统文件 | bool | false | 系统文件 = 带 Windows system 属性的文件；**内置黑名单目录 `$Recycle.Bin`、`System Volume Information` 始终跳过**（与开关无关） |
| 跳过大文件 | bool | false | true 时跳过 **> 1 GiB** 的文件（v1 阈值固定，不可配置），跳过计入统计与日志 |

配置持久化到 `settings` 表（FR-13），下次启动回填。

### FR-3 文件扫描

- 扫描范围：所选目录递归全量（含多层子目录）。
- 采集字段：路径、文件名、扩展名、大小（逻辑大小 `st_size`）、修改时间、创建时间（best-effort，见 §十五 R-2）、是否隐藏/系统。
- **扫描与分类是同一条流水线**：文件被扫描到后立即跑分类规则（§五），写入内存缓冲并批量落库；原始 PRD 的「分类任务」并入扫描任务（§十四 D-5）。
- **不跟随符号链接与 Windows junction**：不下潜、不纳入待整理；计入「跳过数」并记日志（防环、防越出目标目录，沿用 fast-stat P1-1 裁决口径）。
- **始终排除目标输出目录**：`<扫描根>/FilePilot整理/` 本身不参与扫描，避免重复整理上次结果。
- 扫描结果（含分类）在内存中全量保留供预览，并批量写入 SQLite（每 500 条一个事务，10 万级文件不得单条写入）。

### FR-4 实时进度与日志

**进度模型（重要修正）**：

- **扫描阶段为不确定型进度**——目录遍历完成前总文件数不可知，**禁止显示 `5321 / 20000`、百分比或 ETA**（与 fast-stat P0-5 同源裁决，编造的数字比没有数字更糟）。展示：已扫描文件数、扫描速率（files/s）、当前目录、已耗时、跳过数。
- **整理阶段为确定型进度**——整理计划在执行前已固定，展示 `已完成 x / y`、百分比、当前文件、当前目标类别、已耗时。

**日志三类**（均推送到前端实时展示）：

| 类型 | 示例内容 |
|---|---|
| 扫描日志 | `扫描: invoice.pdf · 12MB`（采样：不逐文件全量推送，见 §8.3） |
| 分类日志 | `分析: invoice.pdf · 匹配关键词: invoice · 建议分类: 财务 · 可信度: 95%` |
| 系统日志 | `扫描任务启动: 并发=8 · Task#1`、`扫描完成: 15283 文件 / 823 目录` |

### FR-5 扫描统计

扫描任务结束（完成或取消）后生成，两项分组：

| 分组 | 指标 | 口径 |
|---|---|---|
| 文件统计 | 文件数量 / 目录数量 / 总大小 | 不含目录自身；总大小 = 逻辑大小之和；**单位基数 1024、显示 KB/MB/GB（沿用 fast-stat P0-2/P0-4 口径）** |
| 性能统计 | 扫描耗时 / 平均速度 / 最大并发数 / **跳过错误数** | 跳过错误数 = 权限失败 + 符号链接 + 配置开关跳过（隐藏/系统/大文件）+ 内置黑名单目录，明细最多保留 20 条（展示于日志区） |

耗时精度：≥1s 显示两位小数秒，<1s 显示一位小数毫秒（沿用 fast-stat §3.6）。

**取消扫描**：任务状态 `canceled`，保留已扫描部分统计并明确标注「已取消 · 部分结果」；部分结果**可查看统计但不进入分类预览与整理入口**（防止基于不完整数据整理），需重新扫描。

### FR-6 智能分类

规则引擎驱动，算法与规则表见 §五。每文件产出：目标类别、置信度、原因、来源（规则/用户）。分类在扫描流水线中完成，非独立任务。

### FR-7 分类预览与详情

- 汇总视图：按类别列出 `类别 · N 个文件`（7 类固定顺序：图片、视频、文档、财务、工作、学习、其他），各类别计数由聚合查询得出。
- 详情视图：点击类别进入文件列表，**分页加载（每页 100 条）**，10 万级数据禁止一次性渲染全量 DOM。
- 每行展示：文件名、路径、大小、目标类别、置信度、原因（如 `命中关键词: 合同`）。

### FR-8 分类调整

预览阶段允许逐文件调整，**调整即时落库、立即生效于后续整理计划**：

| 操作 | 语义 |
|---|---|
| 重新指派类别 | 改为 7 类之一；来源标记改为「用户」，置信度展示为「手动」，原因展示 `用户手动指定` |
| 排除出本次整理 | 该文件不参与本次移动；`excluded=1`，保留在列表中可恢复 |

批量操作、规则整体重跑不在 v1（§2.2）。

### FR-9 执行整理

**前置**：用户点击「开始整理」→ **必须弹二次确认**，展示 `即将整理: 文件数量 N · 目标目录 <扫描根>/FilePilot整理 · 是否继续？[取消] [确认]`。取消则不产生任何文件系统写操作。

**执行语义（安全关键）**：

1. 预检：创建目标目录 `<扫描根>/FilePilot整理/<类别>/`；创建失败（不可写）→ 任务直接失败，不动任何文件。
2. 仅移动 `excluded=0` 的文件；按类别移动到对应子目录。
3. 移动 = **同卷 `os.Rename`**（目标目录固定在扫描根内，保证同卷）；**不复制、不删除、不改写内容**。
4. **同名冲突**：目标已存在时追加序号生成 `原名 (n).扩展名`（n 从 1 递增至不冲突），**绝不覆盖**；生成结果记入操作记录。
5. 顺序执行（rename 为毫秒级本地操作），单文件失败（占用/权限）→ 记录失败、**继续执行**，不中断任务。
6. 每次移动立即写 `operations` 表（成功/失败/原因），保证可撤销、可审计。
7. 可取消：取消后已完成的移动保留，任务状态 `canceled`，报告标注部分完成；**撤销对部分完成任务同样有效**（仅回移成功项）。

**「释放空间」指标裁决**：移动文件不释放任何磁盘空间，原 PRD §5.13 的「释放空间: 2GB」为缺陷，改为 **「已移动数据量」**（§十四 D-6）。

### FR-10 整理报告

任务结束（完成/失败/取消）后展示：成功数、失败数（含失败原因明细入口）、耗时、**已移动数据量**、任务状态（`完成 / 已取消·部分完成`）。

### FR-11 撤销上一次整理

| 项 | 需求 |
|---|---|
| 范围 | 仅**最近一次**整理任务（含部分完成的任务）；更早的不可撤销（v1） |
| 入口 | 整理报告页「撤销本次整理」按钮，**必须二次确认** |
| 算法 | 读取该任务全部 `status=success` 的 move 操作记录，逐条反向移动：目标存在 **且** 原路径空缺 → 移回；原路径已被占用 → 该条标记失败并继续 |
| 记录 | 撤销本身作为 `action=undo` 操作写入 `operations`，该整理任务标记 `undone` |
| 重复撤销 | 已撤销的任务再次撤销 → 返回业务错误 `该整理已撤销`，前端友好提示 |
| 中断 | 撤销可取消，语义同整理（已完成的回移保留） |

### FR-12 任务管理

- 任务类型：**扫描任务（含分类流水线）、整理任务**两类；原始 PRD 的「分类任务」并入扫描任务（§十四 D-5）。
- 状态集合：`pending 等待 / running 执行中 / completed 完成 / failed 失败 / canceled 取消`；枚举预留 `paused` 但 v1 不激活（§十四 D-4）。
- 状态转换合法表见 §6.2；非法转换必须拒绝并返回错误，不得静默。
- **单活动任务**：存在 running 任务时启动新任务 → 返回业务错误（前端提示「当前有任务进行中」）。
- **异常恢复**：应用启动时发现数据库中遗留 `running` 任务（上次异常退出）→ 标记 `failed`，原因 `应用中断`，并提示用户。
- 任务状态变更通过事件推送前端（§8.2），前端任何时刻可查询当前任务状态以恢复 UI。

### FR-13 数据持久化（SQLite）

表结构见 §七。覆盖：扫描记录、文件索引（含分类结果与原因）、操作记录（移动与撤销）、任务记录、设置（扫描配置 + 最近 5 条目录）。

## 五、 分类规则引擎与置信度 (Classification Engine)

### 5.1 类别体系（固定 7 类）

`图片、视频、文档、财务、工作、学习、其他`

- 类别即目标子目录名，**仅这 7 个**；原始 PRD 中「工作资料/财务资料」写法统一为「工作/财务」（§十四 D-15）。
- 「其他」为兜底类别，任何规则未命中即归入。
- 新增类别（音频、压缩包等）不在 v1，见 §2.2 与 §十五 R-1。

### 5.2 三类规则与评分算法（可复算、确定性）

对每个文件独立统计**命中项**（匹配前统一小写），命中项计分如下：

| 规则源 | 计分 | 说明 |
|---|---|---|
| 扩展名命中（§5.3） | +60 | 命中媒体类型映射，唯一类别 |
| 文件名关键词命中（§5.4） | 每个 +35，同一类别封顶 +70 | 对**小写化后的文件名（不含扩展名）**做子串匹配，中英文均不区分大小写 |
| 所在路径规则命中（§5.5） | 每条 +20，同一类别封顶 +20 | 对小写化后的完整路径做子串匹配 |

**选类与置信度（口径 B，需求方裁决 2026-10-15）**：

1. 令 `matched = 至少命中一条规则的类别集合`。
2. `matched` 为空 → 类别 `其他`、置信度 `0`、原因 `未命中任何规则`——**不编造数字**。
3. 否则类别 = `matched` 中**优先级最高**者，优先级固定为 `财务 > 工作 > 学习 > 视频 > 图片 > 文档 > 其他`（语义类天然优先于媒体类型类，故不产生平局）。
4. `置信度 = min(100, 所有命中项分数之和)`——**跨类别求和**，与选类无关（0–100 整数，展示为 `NN%`）。
5. 用户手动调整的文件：来源=用户，置信度展示 `手动`。

**校验示例**（表格驱动测试基准，全部可复算）：

| 文件 | 命中项 | matched | 结果 | 原因 |
|---|---|---|---|---|
| `合同.pdf` | pdf→文档 60；「合同」→工作 35 | {文档, 工作} | **工作 95%**（与原始 PRD §5.9 示例一致） | 命中关键词: 合同 |
| `发票2025.pdf` | pdf→文档 60；「发票」→财务 35 | {文档, 财务} | 财务 95% | 命中关键词: 发票 |
| `photo.jpg` | jpg→图片 60 | {图片} | 图片 60% | 扩展名 .jpg → 图片 |
| `README`（无扩展名，无关键词） | 无 | {} | 其他 0% | 未命中任何规则 |
| `项目方案.docx` | docx→文档 60；「项目」「方案」→工作 35×2 | {文档, 工作} | 工作 100%（130 截顶） | 命中关键词: 项目 |
| `D:/合同/a.pdf` | pdf→文档 60；路径「合同」→工作 20 | {文档, 工作} | 工作 80% | 路径命中: 合同 |

> **修订说明（R3）**：原表述「类别得分 = 扩展名分 + 关键词分 + 路径分」「得分最高者为推荐类别」与示例 `合同.pdf → 工作 95%` 自相矛盾（按字面应得 `文档 60%`）。需求方裁决采用**口径 B**：语义优先选类 + 置信度取跨类别总分封顶 100，原始 4 个示例全部成立。推导与用例见 [`requirements-analysis.md`](requirements-analysis.md) §2.1。

### 5.6 置信度与原因

原因字段为面向用户展示的短语，取**决定该类别的命中项**中分值最高者（配合 §5.2 口径 B 的选类规则）；若并列，先按「扩展名 > 关键词 > 路径」，仍并列则按 §5.3 / §5.4 / §5.5 表格声明顺序取第一个，保证**确定性**。格式：`命中关键词: 合同` / `扩展名 .pdf → 文档` / `路径命中: 合同` / `未命中任何规则` / `用户手动指定`。分类日志（FR-4）与详情列表（FR-7）复用同一原因字符串，保证前后端一致。

### 5.7 规则配置化边界

v1 规则**不可通过 UI 编辑**、不提供配置文件入口（§2.2）。规则表常量集中定义于 classifier 模块单点，配套表格驱动测试锁定行为（§十六 DoD）。

## 六、 任务模型与状态机 (Task & State Machine)

### 6.1 任务类型

| 类型 | 覆盖阶段 | 进度模型 |
|---|---|---|
| `scan` | 递归扫描 + 实时分类流水线 | 不确定型（无总数/百分比/ETA） |
| `organize` | 确认后的文件移动（含撤销任务） | 确定型（x / y + 百分比） |

### 6.2 状态机（v1 激活 5 态）

```text
pending ──start──► running ──finish───► completed
   │                 │  │
   │                 │  └──error──────► failed
   │                 └────cancel───────► canceled
   └──（未启动即取消/关闭）────────────► canceled
```

- 合法转换仅上图所示；其余转换（如 `completed → running`、`failed → completed`）必须拒绝。
- `paused` 为预留枚举，v1 无任何转换可到达（§十四 D-4）。
- `failed` 与 `canceled` 必须携带原因字段；`canceled` 允许携带部分结果（统计/部分移动记录）。

### 6.3 单活动任务与并发

- 任一时刻至多一个 `running` 任务（扫描或整理互斥）；并发启动请求返回业务错误。
- 扫描内部并发（FR-2 配置的 worker 数）只作用于单个扫描任务内部；worker 池必须有界、响应取消、退出前 `Wait`（`AGENTS.md` §17，禁止 `errgroup.SetLimit` 递归派发的自死锁写法）。
- 整理为顺序执行（FR-9），不引入额外并发。

## 七、 数据模型 (SQLite Schema)

驱动：`modernc.org/sqlite`（纯 Go，需求方裁决 D-2）。库文件位置：Wails 应用数据目录（如 `%APPDATA%/FilePilot/file-pilot.db`）。所有 SQL 参数化，禁止拼接（`AGENTS.md` §22.1）。

| 表 | 关键字段 | 说明 |
|---|---|---|
| `scans` | `id` PK, `root_path`, `status`, `started_at`, `finished_at`, `duration_ms`, `file_count`, `dir_count`, `total_size_bytes`, `skipped_count`, `avg_speed`, `max_workers` | 一次扫描一行；统计口径见 FR-5 |
| `files` | `id` PK, `scan_id` FK, `path`, `name`, `ext`, `size_bytes`, `mtime`, `ctime NULL`, `category`, `confidence INT NULL`, `source`(`rule`\|`user`), `reason`, `excluded INT` | 10 万级/次；**索引 `(scan_id, category, id)`** 供分类计数与分页 |
| `tasks` | `id` PK, `type`(`scan`\|`organize`), `status`, `scan_id NULL`, `started_at`, `finished_at`, `error`, `undone INT` | 状态机持久化；`undone` 供 FR-11 判重 |
| `operations` | `id` PK, `task_id` FK, `action`(`move`\|`undo`), `src_path`, `dst_path`, `status`(`success`\|`failed`), `error`, `created_at` | 移动与撤销逐条记录；撤销的数据源 |
| `settings` | `key` PK, `value` | JSON 值：`scan_config`、`recent_dirs`（最多 5 条） |

约束与运维：

- 写入批量化的事务边界：扫描期每 500 条 `files` 一批；操作记录**逐条同步写**（撤销依赖它，不可批量延迟）。
- **保留策略**：仅保留最近 **20** 次扫描及其 `files`/`tasks`/`operations` 级联数据，启动时清理更旧记录（防止无限膨胀）。
- Migration：采用版本化 schema（`schema_version` 表 + 嵌入式 SQL 步进），不修改已应用版本（`AGENTS.md` §22.4）。
- 不适用条款豁免：本项目无 MySQL/Redis，`database.md` 的字符集/引擎/InnoDB/GORM N+1/Redis TTL 条款不适用；参数化、禁 `SELECT *`、事务边界、Migration 版本化条款**适用**。

### 8.2 事件（Go → JS 推送）

| 事件名 | 载荷（要点） | 触发 |
|---|---|---|
| `task:status` | `task_id, type, status, scan_id, error` | 状态机每次合法转换 |
| `task:progress` | `task_id, scanned?, rate?, current_dir?, done?, total?, percent?, current_file?, target_category?, elapsed_ms` | 扫描/整理进度（字段按任务类型取舍） |
| `task:log` | `task_id, entries[] {ts, kind: scan\|classify\|system, text}` | 三类日志，**批量数组** |

### 8.3 节流、批量与降载（性能硬约束）

- 进度事件发送间隔 **≥ 200ms**（节流器在后端统一控制），禁止每文件一个事件。
- 日志事件按 **200ms 窗口批量**聚合；单窗口最多 20 条，超出**采样丢弃**并累计 `dropped` 计数（在下一条系统日志中披露 `已丢弃 N 条明细`）。
- 前端日志区为**环形缓冲，上限 500 行**；分类原因全量存库，UI 丢弃不丢数据。
- 文件列表分页（FR-7），禁止全量渲染。

### 8.4 错误契约

- 后端以哨兵错误表达业务语义（`ErrTaskRunning`、`ErrNothingToUndo`、`ErrAlreadyUndone`、`ErrInvalidWorkers` 等），`errors.Is` 判定，禁止字符串比对（`AGENTS.md` §9.5）。
- 前端维护「哨兵 → 友好文案」映射表；已定文案：`请选择扫描目录后继续`、`目录选择失败 / 用户取消操作`、`当前有任务进行中`、`该整理已撤销`。未映射错误展示通用文案 + 记录详情到诊断日志，**禁止把原始 Go error 直接堆给用户**（`AGENTS.md` §65），但诊断日志保留完整链路。

整体风格：简洁、现代、工具软件、强反馈。窗口尺寸适配 1280×800 起。

## 十、 非功能需求 (Non-functional Requirements)

### NFR-1 性能验收

> **状态：正式验收目标**（源 PRD §6.4），验证方式随 Phase 记录到项目 README。

| 指标 | 目标 | 验证方式 |
|---|---|---|
| 扫描吞吐 | SSD 环境 10 万文件 **≤ 60s**（默认并发） | 固定数据集人工基准，记录环境与数据 |
| UI 不卡顿 | 扫描/整理期间 UI 可交互、日志滚动不冻结 | 手动验收 + 事件节流契约（§8.3）保证 |
| 内存 | 峰值不随文件数线性暴涨（缓冲批量落库、日志环形缓冲） | 10 万文件扫描观察 RSS |
| 整理吞吐 | 10 万文件移动 ≤ 60s（顺序 rename，本地操作） | 基准 |

### NFR-2 稳定性

- 大目录、长时间运行不崩溃、不泄漏 goroutine（退出前全部收敛）。
- 应用异常退出后重启：遗留 running 任务置 failed、数据一致（FR-12 异常恢复）。
- 任何单文件错误不得中断整体任务（权限/占用/冲突均按 §十二 处理）。
- 优雅退出：窗口关闭时取消活动任务并等待收尾（最多 3s 超时强退），不留 `running` 谎言。

### NFR-3 兼容性与工程

- v1 目标平台 **Windows 10/11**（WebView2 运行时为前置环境，写入 README）；代码层面路径一律 `filepath` 处理，为 macOS/Linux 留余地。
- Go 版本以根 `go.mod` 为准（当前 `go 1.25`）；本项目使用**独立 `go.mod`**（§十三、D-1）。
- 构建与开发命令入项目 `Makefile`（`dev`/`build`/`test`/`test-race`/`fmt`/`vet`），Windows（PowerShell）执行方式在 README 说明；`fmt` 仅格式化改动文件（规避根 README §9 C2 已知冲突）。
- 日志：`go.uber.org/zap`（白名单内）写诊断日志文件（应用数据目录 `logs/`，单文件 >10MB 时滚动保留 1 个 `.old`，**自实现不引入 lumberjack**）；UI 日志来自事件流而非 zap。禁止记录文件内容与任何凭据。

## 十二、 错误处理矩阵 (Error Handling)

| 场景 | 处理 | 用户可见 |
|---|---|---|
| 扫描：目录/文件权限不足 | 跳过 + 计数 + 记日志；不中断 | 统计中「跳过错误数」+ 日志明细（≤20 条） |
| 扫描：目录不存在/不是目录 | 任务创建阶段失败 | 友好提示，不产生空报告 |
| 整理：目标文件被占用（Windows sharing violation） | 该条标记 failed，**继续** | 报告失败数 + 失败明细（路径 + 原因） |
| 整理：移动失败（权限/跨卷意外/路径超长） | 同上，`error` 落 `operations` | 同上 |
| 整理：目标目录创建失败 | 任务整体失败，**零移动** | `无法创建整理目录: <原因>` |
| 撤销：原路径已被占用 | 该条 failed，继续回移其余 | 撤销报告（成功/失败） |
| 用户：未选目录 / 非法并发数 / 单活动任务冲突 | 边界校验拒绝 | 既有文案（§8.4），不创建任务 |
| 应用：DB 打开/写入失败 | 启动 fail-fast；运行期任务失败 | 启动错误明示；运行期任务置 failed + 提示 |
| 前端：事件洪水 | 按 §8.3 节流/采样 | 系统日志披露丢弃计数 |

错误包装统一 `fmt.Errorf("...: %w", err)`，判别用 `errors.Is/As`；业务代码禁止 `panic`（`AGENTS.md` §10）。

## 十三、 技术架构与模块布局 (Architecture)

### 13.1 技术栈

| 层 | 选型 | 备注 |
|---|---|---|
| 桌面框架 | Wails v2 | 提供窗口、绑定方法、事件、原生目录对话框 |
| 后端 | Go（根 go.mod 为 go 1.25） | 扫描、分类、整理、任务、存储 |
| 前端 | Vue3 + TypeScript + Vite + TailwindCSS | 4 页面 + 弹窗；npm 依赖不受 Go 白名单约束，记录于项目 README |
| 存储 | SQLite（`modernc.org/sqlite`） | 纯 Go、无 CGO（D-2） |
| 日志 | `go.uber.org/zap` | 已在白名单 |

### 13.2 目录布局（独立 module，D-1）

```text
projects/file-pilot/
├── go.mod / go.sum              # 独立 module（wails 工具链要求项目本地 go.mod）
├── wails.json                   # Wails v2 项目描述
├── main.go / app.go             # 组合根：装配依赖、事件注册、生命周期
├── Makefile                     # dev/build/test/test-race/fmt/vet
├── README.md                    # 用法、环境前置(WebView2)、验收记录
├── frontend/                    # Vue3 + TS + Tailwind（Vite 工程）
│   └── src/{views,components,stores,api}
└── internal/
    ├── scanner/                 # 递归遍历、并发 worker 池、统计聚合（不感知分类规则）
    ├── classifier/              # 规则引擎：扩展名/关键词/路径 → 类别+置信度+原因（纯函数，§五）
    ├── organizer/               # 整理计划执行：同卷 rename、冲突改名、操作记录（不感知 UI）
    ├── task/                    # 任务状态机、单活动约束、取消、事件节流器
    ├── storage/                 # SQLite repository：scans/files/tasks/operations/settings
    └── app/                     # Wails 绑定方法实现（Transport 层）与事件桥接
```

### 13.3 分层映射（对齐 `architecture.md`，不引入新模式）

```text
app（Wails 绑定 = Transport/Handler）→ task / scanner / classifier / organizer（Service）→ storage（Repository）→ SQLite
```

- 依赖方向单向：`app → task → {scanner, classifier, organizer} → storage`；禁止反向与跨层。
- 接口由消费方定义、构造函数显式注入（`architecture.md` §4）；文件系统操作经小接口抽象以便注入故障测试（沿用 fast-stat `fsx` 可测性思路）。
- 明确不做：HTTP 服务、gin/chi、GORM、Redis、viper、DI 框架、消息队列（本项目无网络面与多环境配置面，`config.md`/`api.md`/`security.md` 的 JWT/限流/安全头条款不适用；`config.md` 的「禁止散落 `os.Getenv`、强类型配置」精神保留——配置收敛于 `ScanConfig` + `settings`）。

### 13.4 依赖白名单前置（🔴 阻塞项，必须先于编码）

`wailsapp/wails/v2` 与 `modernc.org/sqlite` **不在** `docs/development/dependencies.md` 白名单内。按 `docs/README.md` §3：

1. 先修改 `dependencies.md`，新增 §2.1 式「file-pilot 项目级依赖批准记录」，批准：`github.com/wailsapp/wails/v2`（桌面框架，形态决定，不可用标准库替代）、`modernc.org/sqlite`（纯 Go SQLite，D-2 裁决）及其声明的传递依赖；zap 已在通用白名单。
2. 经 Code Review 通过后，才允许 `go get` 并修改代码；变更后 `go mod tidy` + `go test ./...` + 检查 `go.mod/go.sum` diff 无级联升级。
3. 禁止顺手引入其他依赖（进度条、UI 组件库后端侧、lumberjack 等均不需要）。
